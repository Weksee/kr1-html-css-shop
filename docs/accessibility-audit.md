# Аудит доступности и адаптивности (подготовка к КР №4)

## Что проверено и исправлено вручную

| Область | Что сделано |
|---|---|
| Адаптивная вёрстка | Брейкпоинты 960 / 900 / 700 px; меню-бургер на узких экранах (`aria-expanded`, закрытие по Esc); сетки `grid` перестраиваются в 3 / 2 / 1 колонку; на телефоне фильтры каталога стоят над списком |
| Responsive images | У всех `<img>` заданы `width`/`height` (нет скачков вёрстки), `max-width: 100%`, `aspect-ratio` + `object-fit`; ниже первого экрана `loading="lazy"`; hero-фото подключено через `srcset` + `sizes` (`ferrari-sf90-800.jpg`, `ferrari-sf90-1400.jpg`) |
| Адаптивные формы | Форма заявки в 2 колонки на широком экране и в 1 колонку на телефоне; поля на всю ширину; кнопки на телефоне во всю ширину; шрифт полей 16 px (iOS не приближает страницу) |
| Адаптивные таблицы | Таблица характеристик и таблица доставки в обёртке `.table-wrap` с горизонтальной прокруткой; таблица доставки на телефоне превращается в карточки (`data-label`) |
| Изображения и alt | У каждого фото осмысленный `alt` («Ferrari SF90 Stradale — фото автомобиля»); в окне заказа `alt` подставляется скриптом при выборе авто |
| ARIA — только где нужно | Используются: `aria-label` у навигаций (на странице их две), у кнопки-крестика и ссылки «Наверх» (в них нет текста); `aria-current="page"` в меню; `aria-expanded`/`aria-controls` у бургера; `aria-invalid` и `role="alert"` для ошибок формы; `aria-label` у «Подробнее»/«Заказать» (чтобы читалка называла модель); `role="region"` + `aria-label` у прокручиваемых таблиц. Лишних ARIA-атрибутов на обычных элементах нет — всё остальное сделано нативными тегами (`nav`, `main`, `header`, `footer`, `details`, `dialog`, `label`) |
| Меню | В шапке 4 пункта, остальные страницы — на лендинге и в подвале (`nav` с отдельным `aria-label`); кнопка «Звук» у тахометра использует `aria-pressed`, сам циферблат скрыт от скринридеров (`aria-hidden`), т.к. декоративный |
| Прочее | Ссылка «Перейти к содержимому»; видимый фокус (жёлтая рамка 3 px); тёмная тема с контрастом текста не ниже 4.5:1; `prefers-reduced-motion`; уникальные `<title>` и `meta description` на каждой странице |

## Lighthouse

Lighthouse запускается только в браузере, поэтому отчёт нужно снять самому:

1. Открыть сайт (GitHub Pages или `index.html` через Live Server).
2. Chrome → F12 → вкладка **Lighthouse** → отметить **Accessibility** (и по желанию Performance, Best Practices, SEO) → **Analyze page load**.
3. Сохранить скриншот отчёта в `docs/lighthouse/` (например `index-accessibility.png`), для остальных страниц — по желанию.
4. Если что-то найдено — исправить и написать в таблицу ниже.

| Страница | Accessibility (до) | Accessibility (после) | Что исправлено |
